# Robbe Van Aken, portfolio site

Personal site for Robbe Van Aken, a developer (Craft CMS, Laravel) with a background in design, "Freelancer" in the header (`nav.role`, also the loader and JSON-LD), "Digital craftsman" as the hero's first line, based in Ghent. It replaces the old Booold brand. Goal: an Awwwards Site of the Day. Development leads the positioning, branding is offered more quietly, and copy should never suggest he works strictly alone (he brings in people on bigger projects).

Hosting and deploy (Combell, `.htaccess`, mail, caching, analytics, go-live checklist): see `HOSTING.md`. Google Analytics (GA4 via gtag.js behind the cookie consent; one GA4 setting left to switch off): `ANALYTICS.md`. Email on the domain (a Combell mailbox, then swapping the Gmail address out of the site): checklist in `EMAIL.md`.

## Stack

Astro (static), plain JS modules, GSAP (ScrollTrigger, ScrambleText, SplitText) + Lenis, swup (page transitions, + head and preload plugins). No framework components. `npm run dev` / `npm run build`.

## Class and hook conventions

- Namespaced BEM: `o-` objects (`o-container` = page margins, `o-grid` = the column grid, used together), `c-` components (`c-site-header__nav-link`, modifiers `--name`), `u-` utilities (`u-text-hero/display/h2/lead/body-l/ui/label/muted`, `u-sr-only`). State classes: `is-*` (`is-hidden`, `is-open`, `is-in`, `is-on`, `is-off`).
- JS never selects on styling classes: it uses `data-` attributes (`data-site-header`, `data-menu-toggle`, `data-featured-projects` + `data-fp-*` (item, card, media, clone), `data-services` / `data-services-pin` / `data-service` / `data-service-slot`, `data-approach` + `data-approach-*` (viewport, track, item, frame, progress, bar, count), `data-r-pointer`, `data-marquee`, `data-reveal`, `data-highlight-text`, `data-scroll-next-*`, `data-debug-grid`, `data-skip-link`, `data-cookie-settings`). Exceptions: the R anchor ids (`#a-hero`, `#a-pitch`, `#a-craft`, `#a-foot`), `#r-canvas`, and the dev HUD ids.
- The dev HUD (Glyph/Grid, bottom right) and the grid overlay only render in `npm run dev`, never in the build.

## Head, accessibility, robustness

- `Base.astro` sets the canonical (no trailing slash and no `.html`, like the links and the sitemap; `Astro.url.pathname` ends in `.html` with `build.format: 'file'`, so it's stripped there and in `Nav.astro`'s current-page check), Open Graph + Twitter tags with `public/og.png` (1200×630, `meta.image` in `site.ts`); `noindex` prop for pages to keep out of search.

## The core idea: one R that travels

A blackletter R (source: `public/R.svg`, path in `src/scripts/r-journey/r-shape.js`) is sampled into particles once and then moves through the whole page on a fixed full-screen canvas (`#r-canvas`). It is one object throughout; nothing is swapped.

States are defined by elements with `data-stage` (the engine blends between them based on scroll):

| stage | section           | what the R does                                                                                   | anchor element        |
| ----- | ----------------- | ------------------------------------------------------------------------------------------------- | --------------------- |
| 0     | Hero              | big, extruded 3D, tumbles with the mouse                                                          | `#a-hero`             |
| 1     | Pitch (`#about`)  | "exploded view": fragments slightly apart, still readable                                         | `#a-pitch`            |
| 2     | Projects          | small at the top center (sticky), turns with the mouse                                            | `#a-craft`            |
| 3     | Services (pinned) | the whole R becomes one big 3D icon, morphing into the next service's icon on scroll              | `[data-service-slot]` |
| 4     | Footer            | big again, pixels get pushed away by the cursor                                                   | `#a-foot`             |
| 6     | How I work        | an arrow (the last icon in `drawIcon`) riding the reel's progress line, facing the way you scroll | `[data-r-pointer]`    |

(5 is the loader's copy of stage 2, see `rIntro`.) Stage elements more than one stage apart blend directly (`jump` in `computeS`, with a full turn): services → arrow → footer.

Between stages the R does a full turn around its Y axis. Home order: hero(0) → pitch(1) → services(3) → projects(2 sticky at `#a-craft` + 2 end) → pricing(2 self) (the manifesto between them) → footer(4) — stage numbers index looks/rotations, the document order drives the journey (`computeS` blends neighbours by screen position; more than one stage apart = a direct `jump` with a full turn, e.g. pitch → the services' hold, pricing → footer). The projects section uses stage 2 twice (its sticky head `#a-craft` and an end marker), so the R holds still while the projects pass; the manifesto and the pricing stage each hold a stage-2 marker with its own anchor (`data-r-self`; an end marker with `data-r-self="hold"` keeps the anchor of the stage before it): between two stage-2 elements with different anchors the R GLIDES from one to the other (`ANC`, `a2a` / `a2b` / `a2t` in `computeS`, smoothstep, no turn). Anchors are plain empty elements in the layout, so positions come from CSS and stay responsive.

## Engine (`src/scripts/r-journey/engine.js`)

- `build()`: rasterize the R, create cap particles (front/back face) + side-wall particles (extrusion layers), Voronoi fragments for stage 1, quadrant split + icon assignment for stage 3. Icons are drawn in `drawIcon` (gothic window, split lozenge, star, shield); every particle gets a place in every icon (`IU/IV/IZ…` at `q*N + p`, both sides sorted top to bottom).
- `frame()`: compute scroll state `s`, per-stage rotation matrices, per-particle 3D targets with springs, lighting (light dir `LX/LY/LZ`), then draw.
- The canvas CSS size is set from `innerWidth`/`innerHeight` in `resize()` (CSS `100vh` is taller than the visible area on iOS and would stretch the drawing).
- Slow devices: when a frame's own work averages over ~10 ms the engine renders every other frame, with springs (`K2`) and lerps doubled so the motion speed stays the same.
- Touch: a finger pushes the footer R's pixels too (touchstart/touchmove), without turning the R.
- Rendering: **halftone** (`LOOK` in `r-journey/looks.js`, chosen from seven looks compared side by side: fine crosses with dither, crosses without, calm crosses, a cross edge with dots, halftone, a checker, the old glyphs; the others were too busy). One screen grid of cells, about one particle each (`cell`: 1.25 pitches, 1.4 on the two biggest R's: pitch + footer); the front face is a square per cell sized by its light (four sizes, the darkest tone), the side walls small squares in four tones, no dithering, so flat areas stay calm. Light mode gets more ink (bigger squares, tones shifted darker: `lb`), dark on paper reads thinner. Small R's (<140px) have their own look (`SMALLS`, solid shaded cells). The other looks stay in `LOOKS` (the engine's `look` option); the dev HUD / `G` cycles the old renderers.

Tunables worth knowing:

- `DEPTH` extrusion thickness; `RY/RX/RZ[...]` rotation amounts per stage (in `frame`).
- `DENS[]` particle size per stage (lower = looser).
- Icons: `drawIcon` = the four service icons + the arrow (always last, `NI-1`; the services use `NI-1` icons). The arrow is drawn in the icons' gothic hand: a pointed-arch head with a pointed arch cut out of it (like the window) on a broad shaft (tried: a chevron cut + lozenge terminal, too busy as glyphs at this size; a split head; a notched tail); its pointer is 112px (phones 60), its box kept on the line (the fill's head mapped onto half a box in from either end). The reel's foot (line + arrow; no count, the cards have one) only shows while the stage is pinned. Cards wait at 35% (`DIM`; full with reduced motion or without JS). The arrow sways on `MA` and turns round with `flip` (the pointer's `data-dir`).
- Glyph look per theme in `G` (`gamma`: >1 = more cells bright crosses, a heavier R; `colors` [dim, bright]; cross weight `line` and inset `pad`, heavier and the crosses start touching into a mesh). Dark: gamma 2, `#8d817a` / `#fff`, .32 / .23. Light needs more to read as clearly (dark on light looks thinner and greyer): gamma 3, a pale dim `#c2b8af` so the shaded sides fall back, `#140b08`, .37 / .21. Grid size `CELL` in the glyph draw block.
- `PAL` colour ramp for pixel mode.

## Design rules

- `::selection` is the accent red with light text (`--on-accent`).
- Paper grain over the whole site (`.c-grain` in `Base.astro`, `_grain.css`, outside `#swup`, z 200 above the loader and banners, `pointer-events:none`, hidden in print): still, never animated; an SVG `feTurbulence` tile as a mask on a fill in `--fg`, so it follows every theme; strength `--grain` per theme in `_tokens.css`. No `mix-blend-mode` (it would recomposite the R canvas beneath every frame).
- Palette tokens in `src/styles/base/_tokens.css` `:root` (dark warm brown `#170e0b`, a deep red accent `#c1121f`, used sparingly (was: orange `#ff4a00`; text ON the accent is light paper `--on-accent` #f3eee8, 5.6:1 — dark ink only reached 2.9:1 on the red; `--ink` stays the dark text on paper)). Text is only ever `--fg` (white `#FFFFFF`; light theme: `#170e0b` on `#f3eee8`) or `--muted` (grey `#B2B2B2`; light theme: `#6f6560`), as in Figma. Never hardcode colours: use the tokens so both themes work.
- Inter Tight for all type, self-hosted (no Google Fonts requests). Headings wrap balanced, paragraphs `text-wrap:pretty` (`_document.css`: no lone word on a last line); a hyphenated word that must not split gets a non-breaking hyphen (`\u2011`). The R is the one bold element; keep everything around it quiet.
- Copy: English, sentence case, plain and honest, "not salesy, not slimy". Key line: "Solid code, thoughtful design, genuine care for the craft, and AI where it actually helps. I want to build something we're both proud of. That's the whole pitch."
- Respect `prefers-reduced-motion` (engine and GSAP already do).
- Extreme heights: R anchors use `clamp(min, Nvh, max)` heights, the pitch R is also capped by its box width.
