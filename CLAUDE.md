# Robbe Van Aken, portfolio site

Personal site for Robbe Van Aken, a developer (Craft CMS, Laravel) with a background in design, "Freelancer" in the header (`nav.role`, also the loader and JSON-LD), "Digital craftsman" as the hero's first line, based in Ghent. It replaces the old Booold brand. Goal: an Awwwards Site of the Day. Development leads the positioning, branding is offered more quietly, and copy should never suggest he works strictly alone (he brings in people on bigger projects).

Hosting and deploy (Combell, `.htaccess`, mail, caching, GTM setup, go-live checklist): see `HOSTING.md`.

## Stack

Astro (static), plain JS modules, GSAP (ScrollTrigger, ScrambleText, SplitText) + Lenis, swup (page transitions, + head and preload plugins). No framework components. `npm run dev` / `npm run build`.

## File structure (same conventions as the woonpact project, without Tailwind)

- `src/data/` all copy. `site.ts` (per section, in page order, plus `socials` for footer + mobile menu), `pages.ts` (subpages), `clients.ts`, `projects.ts`, `services.ts`. Change text here, not in components.
- `src/components/sections/` one file per page section, `ui/` small reusable pieces (Button, Icon, Corners, Marquee (props: text, icon, fill), Placeholder, ThemeToggle), `layout/` Nav, PageTransition (the page loader overlay, in `Base.astro`) + dev-only DevHud and GridOverlay. Components contain markup only: no `<style>` or `<script>`.
- `src/styles/main.css` imports, in order: `base/` (`_fonts.css`: self-hosted Inter Tight @font-face (files in `public/fonts`, OFL license alongside, latin 400/500 preloaded in `Base.astro`); `_tokens.css`: colours, grid, type scale, spacing, eases; `_document.css`: reset, selection, R canvas) → `objects/` (`_container.css`, `_grid.css`) → `components/` (one `_name.css` per component, imported alphabetically in `index.css`) → `utilities/` (`_text.css`, `_screen-reader.css`) → `vendor/` (`_cookieconsent.css`).
- `src/scripts/main.js` is the only script entry (loaded from `layouts/Base.astro`). Once: eases, theme, Lenis, cookie consent, page transitions. Per page: `mount()` runs every page init again after each swup swap, with the page's container as `root`; each init does nothing when its element is missing and returns a cleanup (window listeners via an AbortController, ticker callbacks removed, ScrollTriggers killed), which `unmount()` calls before the content is replaced. New page scripts must follow this. `global/` (eases, theme, lenis, siteHeader, reveal, cookieConsent, debugGrid, pageTransitions), `components/` (approach, workFilter, workLoop, filter, workIntro, cardCursor, openProject, contactForm, glyphHover (parked), scrollNext, services, marquee, highlightText, textHover), `r-journey/` (the R engine).
- `public/clients/` client logos (white SVG, one file per logo).
- `src/assets/projects/` project images, per project in `<slug>/`: `hero.jpg` (its site's home, 1440×900 @2x), `mockup.jpg` (a device mockup, from the PSDs in ~/Downloads/Cool Mockups, composited with psd-tools: the screenshot in the smart object's perspective, the PSD's own shadow / glare layers on top, toned down where they dulled the site's colours), `desktop-1|2.jpg` (1440×900 @2x) and `mobile-1|2.jpg` (390×844 @3x) screenshots; Toran: `toran.jpg` + `toran/photo-*.jpg` (photos from toran.be only, never screens of its site or software). The main visual (`ui/ProjectVisual.astro`, `_visual.css`), the same on the card, the detail page and the scroll-next section: `image`, the device mockup (Toran: its helicopter photo) filling the box, focus `position`. (Tried and dropped for the cards: flat screenshots on brand-colour or tinted fields, centred or running past the box: they never felt as good as the mockups. `shot` + `field` still work.) The case study's visuals are from other pages than the home (each project: a desktop screen + two phone screens of its subpages; Toran: its website only, never the software). `ui/ProjectImage.astro` renders every image as a `<picture>` (AVIF + WebP + JPEG, widths up to the source, `display:contents`); the main visual always uses its default `sizes` (`92vw`), so card, detail page and scroll-next pick the same file and the transitions hand over to an image that's already loaded (checked: no new request).

## Class and hook conventions

- Namespaced BEM: `o-` objects (`o-container` = page margins, `o-grid` = the column grid, used together), `c-` components (`c-site-header__nav-link`, modifiers `--name`), `u-` utilities (`u-text-hero/display/h2/lead/body-l/ui/label/muted`, `u-sr-only`). State classes: `is-*` (`is-hidden`, `is-open`, `is-in`, `is-on`, `is-off`).
- JS never selects on styling classes: it uses `data-` attributes (`data-site-header`, `data-menu-toggle`, `data-featured-projects` + `data-fp-*` (item, card, media, clone), `data-services` / `data-services-pin` / `data-service` / `data-service-slot`, `data-approach` + `data-approach-*` (viewport, track, item, frame, progress, bar, count), `data-r-pointer`, `data-marquee`, `data-reveal`, `data-highlight-text`, `data-scroll-next-*`, `data-debug-grid`, `data-skip-link`, `data-cookie-settings`, `data-theme-toggle`). Exceptions: the R anchor ids (`#a-hero`, `#a-pitch`, `#a-craft`, `#a-foot`), `#r-canvas`, and the dev HUD ids.
- The dev HUD (Glyph/Grid, bottom right) and the grid overlay only render in `npm run dev`, never in the build.

## Head, accessibility, robustness

- `Base.astro` sets the canonical (no trailing slash and no `.html`, like the links and the sitemap; `Astro.url.pathname` ends in `.html` with `build.format: 'file'`, so it's stripped there and in `Nav.astro`'s current-page check), Open Graph + Twitter tags with `public/og.png` (1200×630, `meta.image` in `site.ts`); `noindex` prop for pages to keep out of search.
- "Skip to content" link (`data-skip-link`) jumps to `main#top` (`tabindex="-1"`, focus moves along via swup's `scroll:anchor`).
- Mobile menu: while open everything next to the header (and the skip link) is `inert`; Escape closes it and returns focus to the toggle. No `overflow:hidden` on `<html>` while it's open (that switches `position:sticky` off: the projects' small R anchor jumped); Lenis stops and the menu + header take no pan gestures (`touch-action:none`, `overscroll-behavior:contain`).
- Highlight texts are hidden from screen readers (`aria: "hidden"`) with a visually hidden copy (same tag) right before them: SplitText's default `aria-label` isn't allowed on `<p>`.
- Structured data: a `Person` JSON-LD block in `Base.astro` (name, role, Ghent, email, socials).
- URLs without a trailing slash everywhere: Astro builds pages as files (`build.format: 'file'`: `work.html`, `work/<slug>.html`) and `public/.htaccess` (Apache) serves them without `.html` and without adding a slash (`DirectorySlash Off`); other hosts need the same rewrite.
- Tap targets: the menu toggle, socials and footer legal links have a 44px hit area (a transparent pseudo-element), nothing moves.
- Project cards: the title is a heading (h3 on home, h2 on /work) and the link's name is "title: description"; the project page's visual has an alt (title + description).
- Images: `loading="lazy"` + `decoding="async"` below the fold, `fetchpriority="high"` on the LCP image (see `ProjectImage`); client logos carry their SVG's width/height.
- Lighthouse (mobile + desktop, all pages 97–100 on every category; /404 SEO is low on purpose: noindex): CSS is inlined in every page (`build.inlineStylesheets: 'always'`), so no stylesheet may be imported lazily from JS (the cookie banner's CSS is a copy in `public/vendor/cookieconsent.css`, linked when the banner loads, with `data-swup-theme` so swup's head plugin keeps it on page swaps: update it with the library); page scripts stay in the main bundle (tried lazy chunks per page: they started later than the other inits and broke the /work filter); the contact wizard's first state (`is-wizard is-first`, `is-current` on step 1) is in the HTML (no layout shift); without JS every question shows via `html.no-js` (removed by the inline theme script in `Base.astro`; never a `<noscript>` style: swup parses fetched pages without scripting, so it would apply after every page swap); light `--muted` / `--subtle` are dark enough for 4.5:1 on the panel. Test: `npm run build`, `npx serve dist`, `npx lighthouse` (cache warnings are local only: `.htaccess` sets the caching).

## Light / dark theme (one theme per visit)

- One theme for the whole visit: no colour changes on scroll or between pages (tried and dropped: a light zone on home, colour "chapters" per section/page with an always-dark overlay and menu; it felt forced, the background was doing the work the content should do). Light is the default; a toggle switches to dark and back. Rhythm comes from the content instead: big type moments (the pitch quote at 40px, set tight, the footer title at ~95px), big project images on home (6–7 columns), the R (the darkest thing on the light page), the two orange bands.
- `Base.astro` renders `html[data-theme="light"]`; its inline script switches to dark before the first paint if `localStorage.mode` is `dark`. `scripts/global/theme.js` keeps it in sync (updates `<meta name="theme-color">`, again in every `mount()` since swup's head plugin restores it).
- Toggle: `ui/ThemeToggle.astro` (`float`, in `Base.astro`, outside `#swup`): a 13px half-filled square on a 36px `--panel` tile, fixed bottom right inside the grid (right edge on the page margin, on the loader counter's line), on every page and every screen; the dark theme turns it half a turn; on hover / keyboard focus a tooltip ("Dark mode" / "Light mode": what a click does, also its accessible name) slides in to its left (punch ease) and out again; hidden during the loader, page swaps, with the menu open, and on phones while the cookie banner shows; the footer's bottom row keeps room for it. Out of the header and the menu (tried: the square in the header, the words in the nav, a text link in the footer). The dev HUD is off (`index.astro`; the grid overlay still works with Shift+G).
- The switch fades: a view transition cross-fades the whole page, R canvas included (`::view-transition-*(root)` in `_document.css`, .6s = `FADE`); without view transitions `html.is-theming` eases every colour token for .6s (they're registered, `@property` in `_tokens.css`); reduced motion: instant.
- Colours only through tokens (`_tokens.css`: `:root` holds the dark values, `:root[data-theme="light"]` the light ones): besides the palette `--on-fg` (text on an `--fg` background, buttons), `--surface` (cookie banner), `--paper` (filling marquee), `--logo-filter` (white client logos turn dark), `--ink` stays dark text on orange in both. Light text is a soft warm dark (`--fg` `#2e2420`), not near-black; the R's light glyphs are darker (`#140b08`). The loader overlay and the mobile menu follow the theme (`--bg` / `--panel`). The R engine picks its glyph / pixel colours per theme (`G`, `PALS`, read from `theme.mode` every frame; sprites cached per theme). Parked `glyphHover.js` still has dark-only colours.
- Easter egg: a hidden third theme, `wild` (risograph inks: ultramarine `--bg`, yellow `--fg`, pink `--muted`, green `--accent` for the bands, the R in orange + lilac: `G` / `FINE` / `PALS` `.wild` in the engine; tokens under `:root[data-theme="wild"]`). Found by pressing R (not while typing) or clicking the toggle three times within 1.1s (`TRIPLE`; clicks during a cross-fade land on `<html>`, so a click on the toggle's spot counts too). This visit only (`sessionStorage.wild`, read by the inline script in `Base.astro`); the toggle (tooltip "Back to normal", the square a turn and a quarter) or R again goes back to the saved light / dark. Hinted at in the footer's bottom row ("Psst… press [R]" with a keyboard + fine pointer, "Psst… tap [◧] three times" on touch, "You found it." while on) and in the console. Listed in `data/cookies.ts`.
- References are for learning, not copying: take the principle (e.g. contrast from content and type scale instead of background changes), build it in this site's own language.

## Cookie consent

`vanilla-cookieconsent` v3 (loaded lazily, when the browser is idle or on "Cookie settings"), started from `scripts/main.js` (all pages; on a first visit only once the loader has finished, so the banner never sits on top of it) via `scripts/global/cookieConsent.js`; theme in `styles/vendor/_cookieconsent.css`. Categories: necessary + analytics (no analytics script exists yet; load one with `type="text/plain" data-category="analytics"`). Everything the site stores (cookies + local/session storage, per category: `cc_cookie`, `mode`, `loaded`; `_ga`, `_ga_*`) is one list in `src/data/cookies.ts`, shown as a table per category in the preferences and as the table in the privacy notice: update it there when that changes. Footer "Cookie settings" reopens the preferences (`data-cookie-settings`, a delegated click so it survives page swaps). The banner is hidden from bots (`hideFromBots`, default), so headless test browsers won't show it unless `navigator.webdriver` is spoofed.

- Google Tag Manager (`GTM-PHRBR9CS`, `layouts/Base.astro`): production builds only (`process.env.NODE_ENV === 'production'`, never in `npm run dev`; `import.meta.env` in Base.astro trips Vite's dev transform, and the snippets are string constants because braces inside a conditional `<script>` are read as template expressions). Consent mode v2 defaults (all denied) are set inline first; the GTM snippet is a `<script type="text/plain" data-category="analytics">`, so cookieconsent runs it only once analytics is accepted (no noscript iframe: it would load without consent). `cookieConsent.js` sends `gtag('consent','update', { analytics_storage })` on consent / change, clears `_ga*` cookies and reloads when analytics is switched off. Page swaps push `{ event: 'page_view_swap', page_path, page_title }` to `dataLayer` (`mount()` in `main.js`): set up a GTM trigger on that custom event for page views after the first. The privacy notice names Google Analytics / Tag Manager and the `_ga` cookies.

## Page transitions (swup, `scripts/global/pageTransitions.js`)

## The core idea: one R that travels

A blackletter R (source: `public/R.svg`, path in `src/scripts/r-journey/r-shape.js`) is sampled into particles once and then moves through the whole page on a fixed full-screen canvas (`#r-canvas`). It is one object throughout; nothing is swapped.

States are defined by elements with `data-stage` (the engine blends between them based on scroll):

| stage | section           | what the R does                                                                                   | anchor element        |
| ----- | ----------------- | ------------------------------------------------------------------------------------------------- | --------------------- |
| 0     | Hero              | big, extruded 3D, tumbles with the mouse                                                          | `#a-hero`             |
| 1     | Pitch (`#about`)  | "exploded view": fragments slightly apart, still readable                                         | `#a-pitch`            |
| 2     | Projects          | small at the top center (sticky), turns with the mouse                                            | `#a-craft`            |
| 3     | Services (pinned) | the whole R becomes one big 3D icon, morphing into the next service's icon on scroll              | `[data-service-slot]` |
| 4     | Footer            | big again, pixels get pushed away by the cursor                                                   | `#a-foot`             |
| 6     | How I work        | an arrow (the last icon in `drawIcon`) riding the reel's progress line, facing the way you scroll | `[data-r-pointer]`    |

(5 is the loader's copy of stage 2, see `rIntro`.) Stage elements more than one stage apart blend directly (`jump` in `computeS`, with a full turn): services → arrow → footer.

Between stages the R does a full turn around its Y axis. The projects section uses stage 2 twice (its sticky head and an end marker), so the R holds still while the projects pass. Anchors are plain empty elements in the layout, so positions come from CSS and stay responsive.

## Engine (`src/scripts/r-journey/engine.js`)

- `build()`: rasterize the R, create cap particles (front/back face) + side-wall particles (extrusion layers), Voronoi fragments for stage 1, quadrant split + icon assignment for stage 3. Icons are drawn in `drawIcon` (gothic window, split lozenge, star, shield); every particle gets a place in every icon (`IU/IV/IZ…` at `q*N + p`, both sides sorted top to bottom).
- `frame()`: compute scroll state `s`, per-stage rotation matrices, per-particle 3D targets with springs, lighting (light dir `LX/LY/LZ`), then draw.
- The canvas CSS size is set from `innerWidth`/`innerHeight` in `resize()` (CSS `100vh` is taller than the visible area on iOS and would stretch the drawing).
- Slow devices: when a frame's own work averages over ~10 ms the engine renders every other frame, with springs (`K2`) and lerps doubled so the motion speed stays the same.
- Touch: a finger pushes the footer R's pixels too (touchstart/touchmove), without turning the R.
- Rendering: **halftone** (`LOOK` in `r-journey/looks.js`, chosen from seven looks compared side by side: fine crosses with dither, crosses without, calm crosses, a cross edge with dots, halftone, a checker, the old glyphs; the others were too busy). One screen grid of cells, about one particle each (`cell`: 1.25 pitches, 1.4 on the two biggest R's: pitch + footer); the front face is a square per cell sized by its light (four sizes, the darkest tone), the side walls small squares in four tones, no dithering, so flat areas stay calm. Light mode gets more ink (bigger squares, tones shifted darker: `lb`), dark on paper reads thinner. Small R's (<140px) have their own look (`SMALLS`, solid shaded cells). The other looks stay in `LOOKS` (the engine's `look` option); the dev HUD / `G` cycles the old renderers.

Tunables worth knowing:

- `DEPTH` extrusion thickness; `RY/RX/RZ[...]` rotation amounts per stage (in `frame`).
- `DENS[]` particle size per stage (lower = looser).
- Icons: `drawIcon` = the four service icons + the arrow (always last, `NI-1`; the services use `NI-1` icons). The arrow is drawn in the icons' gothic hand: a pointed-arch head with a pointed arch cut out of it (like the window) on a broad shaft (tried: a chevron cut + lozenge terminal, too busy as glyphs at this size; a split head; a notched tail); its pointer is 112px (phones 60), its box kept on the line (the fill's head mapped onto half a box in from either end). The reel's foot (line + arrow; no count, the cards have one) only shows while the stage is pinned. Cards wait at 35% (`DIM`; full with reduced motion or without JS). The arrow sways on `MA` and turns round with `flip` (the pointer's `data-dir`).
- Glyph look per theme in `G` (`gamma`: >1 = more cells bright crosses, a heavier R; `colors` [dim, bright]; cross weight `line` and inset `pad`, heavier and the crosses start touching into a mesh). Dark: gamma 2, `#8d817a` / `#fff`, .32 / .23. Light needs more to read as clearly (dark on light looks thinner and greyer): gamma 3, a pale dim `#c2b8af` so the shaded sides fall back, `#140b08`, .37 / .21. Grid size `CELL` in the glyph draw block.
- `PAL` colour ramp for pixel mode.

## Design rules

- `::selection` is orange with dark text.
- Palette tokens in `src/styles/base/_tokens.css` `:root` (dark warm brown `#170e0b`, orange `#ff4a00` accent used sparingly). Text is only ever `--fg` (white `#FFFFFF`; light theme: `#170e0b` on `#f3eee8`) or `--muted` (grey `#B2B2B2`; light theme: `#6f6560`), as in Figma. Never hardcode colours: use the tokens so both themes work.
- Inter Tight for all type, self-hosted (no Google Fonts requests). Headings wrap balanced, paragraphs `text-wrap:pretty` (`_document.css`: no lone word on a last line); a hyphenated word that must not split gets a non-breaking hyphen (`\u2011`). The R is the one bold element; keep everything around it quiet.
- Copy: English, sentence case, plain and honest, "not salesy, not slimy". Key line: "Solid code, thoughtful design, genuine care for the craft, and AI where it actually helps. I want to build something we're both proud of. That's the whole pitch."
- Respect `prefers-reduced-motion` (engine and GSAP already do).
- Extreme heights: R anchors use `clamp(min, Nvh, max)` heights, the pitch R is also capped by its box width.
